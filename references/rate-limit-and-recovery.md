# 请求失败的定位与恢复

## 已在本机验收的取价流程（2026-10-12）

默认接口优先：每个源商品只加载一次自己的任务页，提前开启网络捕获；读取该页原生成功响应及所需上下文，再调用页面官方 SDK，通过 XHR 获取该商品的真实 SKU 价格。禁止把一个商品的设备上下文当成所有源商品通用上下文。

本机两个源商品的 23 个和 12 个 SKU 均已取得 `warePriceGatherVO.finalPrice`，35 行价格/顺序、81 张 JPEG 和 1 个 MP4 已独立校验。重复执行为 0 请求，成功缓存可复用。这是本机验收，不代替同事电脑、全清单或平台长期可用性验收。

## 这次确认的代码问题

- 旧请求只复制签名 URL，却漏了页面自己的 `X-Skuid-Param`、`x-sdx`、`soaRate` 上下文头，并使用与页面不同的 fetch 流程。现使用页面官方 SDK 和 XHR；上下文只驻留页面内存。
- A 商品页上下文调用 B 商品，部分 SKU 超时；换到该 SKU 所属商品页后正常返回。现按源商品重建一次上下文，同族 SKU 走接口，并限制 `allowedSkuIds`。
- `variant_queue.py` 默认输出 SKU 字符串，点击采集器误当规格对象，导致 0 次点击。现新增 `--rows` 并强制检查 `{sku,spec1,spec2}` 对象契约；解析失败不再当空列表跳过。
- 网络捕获启动晚于导航，会错过快速响应。另一个读取问题是 `readNetworkCapture()` 会清空尚未完成的条目，后续 `loadingFinished` 因失去映射而无法补响应体。现捕获先启动、原生响应完成后再读取，OPTIONS 200 不算价格成功。
- 输出路径、空规格的工作簿回读和图片模块缺失导入已修复；测试覆盖真实 CLI、真实 JPEG 转码和商品矩阵回读。

## 不再使用的未证实结论

仅凭超时不能认定账号长期观察期、第二个请求必挂、平台全站封禁或公司内网天然放行。旧 goto 路径还混入浏览器工具的全局注入与错误路由参数，不能据此证明京东正常页面点击必失效。真实原因必须由请求回执、页面状态和正确参数的对照验证确定。

## 错误分流

| 证据 | 行为 |
| --- | --- |
| `finalPrice` 或旧版 `bestPromotion.purchasePrice` 有效 | 按 SKU 精确身份保存到手价 |
| HTTP 200、已登录、页面只给普通 `jdPrice` | `ARRIVAL_PRICE_PENDING`，不编到手价；可保留主数据展开规格 |
| `REQUEST_TIMEOUT` / `INITIAL_RESPONSE_MISSING` | 检查原生上下文、捕获时序、SKU 身份和网络；不直接归因风控 |
| HTTP 403 / 429 / PC 频控页 | 停本轮；429 尊重 Retry-After；不能立即换工具继续撞接口 |
| 京东验证 / 登录失效 | 停下由用户正常验证或登录，不自动重试 |
| 超时后任务未落定 | 先中止并读回任务状态；结果未知不立即重放 |

## 素材缓存恢复

并发商品共享同一图片URL时，直接写JPEG缓存可能让其他线程读到未写完的图片。`jpeg_cache.py`按URL合并下载，完整解码后原子发布缓存与任务暂存文件；完好缓存可零网络修复损坏目标图。下载失败保留原文件，目标越出任务状态目录即拒绝。离线测试覆盖并发、损坏缓存与目标、下载失败及路径边界；此恢复不重放京东价格请求。

## 点击备用

接口确实不可覆盖、但当前正常任务页仍允许普通 SKU 点击时可用 `click_collector.mjs`。它只读页面自然响应，不伪造价格。若页面已进入验证或频控，不因切点击而绕过；恢复后再判断可用路由。

初始保护值是接口/点击 30 秒间隔、商品页 60 秒间隔；它们不是平台规定的安全阈值。27 页约 2.5 分钟曾触发验证，不能再快速连续导航。接口、点击共用 `runner.lock`，失败争锁不能修改他人状态或删除他人锁。

## 2026-10 新增的失败形态

- `LOCAL_OR_TRANSPORT_ERROR` 在同一个商品页连续约 50 次请求后必现（大 SKU 商品最容易）。这是单页状态问题，与频控无关；把单轮请求上限压到 45，让页面及时关闭重开即可，实测整晚不再复发。
- SKU 级 `PRODUCT_UNAVAILABLE` 曾经拦停整批。现在只写 `errors/<sku>.json` 并继续；复核模式下同时打 `priceRecheckedAt`，否则该 SKU 会被每轮重复请求。
- 整批「无促销价」不是取价失败，而是登录态降级：京东只回 `jdPrice`。判定与复核流程见 `throughput-and-stability.md` 的「登录态降级后的价格复核」。
