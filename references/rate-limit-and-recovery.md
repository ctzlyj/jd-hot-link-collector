# 限流与恢复（2026-10-10/11 现场结论）

## 已复现事实

- 单在途请求、有效响应才记成功、共享SKU缓存：45个逐SKU真实价格在30秒级间隔下成功采集；随后仍出现403。
- 403会污染整个会话：触发后，真实规格点击与新的文档导航都可能被重定向到 `pc-frequent-pro.pf.jd.com`（PC频控页，页面文案“暂时无法展示该商品的信息”）。
- “初始文档加载恢复”不等于“接口恢复”：长冷却后商品页文档加载可返回200并携带到手价，但第一个程序化SDK请求立即403；SPA内切换与程序化请求同样受限。
- 触发403后约30分钟的重试仍直接重定向频控页；需要更长冷却。

## 2026-10-12 复核补充

- 约2天冷却后账号完全恢复：文档加载、真实规格点击和单个程序化请求都通过（同一页面内首个程序化请求可成功取价）。
- **静默挂起**：同一页面的第2个及以后的程序化SDK请求会被服务端静默挂起——fetch永不返回、无错误、无403，AbortController也无法使其落定。这是与403不同的独立失败模式；页面本身仍正常。检测方式：页面内job长期停留在FETCH且abort无效。
- **goto重载会杀死页面交互**：对同一标签页执行 `Page.goto` 重载后，真实规格点击完全失效（不产生请求、选中不变）。新建标签页（`newTab`）后点击立即恢复。**采集必须每个商品用新标签页，禁止goto重载后继续点击。**
- **快速连续开页触发验证**：约5.5秒/页的连续27次商品加载触发了 `cfe.m.jd.com` “快速验证”页（与2026-10-08的快速翻页软风控一致）。商品之间必须有充足导航间隔（当前用60秒），只给点击设间隔不够。
- **点击驱动是已验证的可靠路径**：新标签页初始加载返回默认SKU完整数据；按前台顺序点击每个规格按钮（间隔30秒）返回各SKU数据；网络捕获读取即清空缓冲，必须每次读完全部新行并保存全部业务响应。

## 恢复顺序

1. 长冷却后，第一个业务动作必须是 `clean_session_click_test.mjs` 的真实规格点击；禁止先发脚本价格请求。
2. 自然点击返回200且能取到有效到手价 → 才能启动 `collect_signed.mjs`。
3. 自然点击也403 → SPA路径整体受限，停止，等待更长冷却；不要当天反复重试延长限制。

## 分类与熔断

| 现象 | 处理 |
|---|---|
| 403 | 访问拒绝，本轮立即停；递增冷却后单次探测 |
| 429 | 限流，尊重 `Retry-After`，本轮停 |
| PC频控页 | 页面级拒绝，长冷却，先做真实点击测试 |
| 验证页/登录失效 | 停止，交还用户；重新登录不等于验证解除 |
| 程序化请求挂起 | 同页第2个起程序化请求被静默挂起；改用点击驱动，不要重试 |
| 结果未知/超时 | 熔断，不自动重放 |

禁止：换账号、换IP、改端点、绕过验证或把页面保活请求当作采集节奏。图片素材下载与价格接口分离，公开素材用普通UA+来源页Referer。
